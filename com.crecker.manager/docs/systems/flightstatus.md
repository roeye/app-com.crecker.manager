# flightstatus.co.il

אתר מצב טיסות.

- **מזהה מערכת:** `flightstatus`
- **קטגוריה:** אתרים
- **קוד:** `app/src/main/java/com/crecker/manager/systems/flightstatus/`
- **פעולות:** ביצוע cron data retrieval (`cron_data_retrieval`), בדיקת עדכון אחרון (`check_last_update`)
- **שורת סטטוס במסך הבית:** שתי שורות, "משיכת נתונים" ו"בדיקת עדכון". בכל אחת נקודה בצבע הסטטוס, הסטטוס והזמן של ההרצה האחרונה. אם שורה נשברת, הנקודה בגובה השורה הראשונה שלה.

## הגדרות המערכת (⚙ במסך flightstatus.co.il)

פרטי החיבור לשרת של **האתר הזה**. הם נפרדים מהחיבור של paisresults.co.il, ונשמרים ברמת המערכת (`flightstatus/…`). משתמשת בהם "בדיקת עדכון אחרון". "ביצוע cron data retrieval" לא צריכה אותם, כי היא פונה לכתובת באינטרנט.

| שדה | ברירת מחדל | הערות |
|---|---|---|
| פרוטוקול | FTP | FTP / FTPS / SFTP. ב-FTP רגיל הסיסמה עוברת ללא הצפנה. |
| שרת (host) | — | חובה |
| פורט | ריק (21 ל-FTP/FTPS, 22 ל-SFTP) | |
| שם משתמש | — | חובה |
| סיסמה | — | חובה. נשמרת **מוצפנת** (Keystore). שדה ריק בשמירה משאיר את הסיסמה הקיימת. |
| תיקיית יעד | `/flightstatus.co.il/data` | התיקייה שבה נבדק הקובץ. |

כפתור **בדיקת חיבור** מתחבר לשרת עם הערכים שבטופס (גם לפני שמירה) ומוודא שתיקיית היעד קיימת, ויוצר אותה אם צריך.

אם חסרים פרטים, "בדיקת עדכון אחרון" נכשלת מיד עם הודעה שמפנה להגדרות המערכת.

## פעולה: ביצוע cron data retrieval

- **מזהה:** `cron_data_retrieval`
- **קוד:** `CronDataRetrieval.kt`

> מריצה ידנית את סקריפט ה-cron job של האתר בשרת, למקרה שההרצה האוטומטית לא קרתה או נכשלה. מציגה את קוד ה-HTTP, כמה זמן לקחה הריצה ואת הפלט של הסקריפט.

- **כתובת:** `https://www.flightstatus.co.il/cronjobs/data_retrieval.php`. הכתובת קבועה בקוד (`CronDataRetrieval.URL`), ואין לה הגדרה.
- **ידנית בלבד:** אין לפעולה הגדרות ואין תזמון, כי ה-cron job בשרת כבר מריץ את הסקריפט באופן אוטומטי.

### מה היא עושה

1. **בקשת GET אחת** לכתובת, עם User-Agent של דפדפן. מחכים לתשובה עד **5 דקות**, כי הסקריפט עושה עבודה אמיתית ולוקח זמן.
   - **בלי ניסיונות חוזרים:** הרצה כפולה של הסקריפט בשרת לא בהכרח בטוחה.
   - **ביטול** באפליקציה מפסיק רק את ההמתנה לתשובה. אם הבקשה כבר הגיעה לשרת, הסקריפט ממשיך לרוץ שם.
2. **תוצאה בלוג:** `HTTP 200 · זמן ריצה 3.2 שנ׳ · 1.4 KB`. זמן הריצה נמדד מתחילת הבקשה ועד שכל התשובה התקבלה. מתחת לדקה הוא מוצג בעשיריות שנייה, ומעל דקה כ"2 דק׳ 5 שנ׳". אם הבקשה נכשלה (אין רשת, timeout וכו'), מוצגת הסיבה ואחרי כמה זמן היא נכשלה.
3. **הפלט של הסקריפט** מוצג בלוג כבלוק נפרד: גופן קבוע, בלי שבירת שורות וגלילה אופקית. בכותרת הבלוק מופיע ה-Content-Type. הפלט נשמר בהיסטוריה ונכלל בהעתקה ובשיתוף.
   - **אם התשובה היא HTML** (גם PHP שמדפיס טקסט רגיל שולח `text/html`), היא מומרת לטקסט קריא:
     - `<br>` ותגיות סוגרות של בלוקים (`</p>`, `</div>`, `</tr>`…) הופכות לשורה חדשה.
     - `<script>`, `<style>`, `<head>` והערות נמחקים, וכל שאר התגיות נמחקות.
     - ‏entities מפוענחים (`&amp;`, `&#233;`…).
     - שורות חדשות שכבר יש בטקסט נשמרות, ו-`<br>` שאחריו שורה חדשה נספר כשורה אחת.
   - הקידוד נקבע לפי ה-`charset` שב-Content-Type, וברירת המחדל היא UTF-8.
   - פלט ארוך מ-30,000 תווים נחתך, ומופיעה הודעה כמה תווים הוצגו מתוך כמה.
   - אם אין פלט, מופיע "הסקריפט לא החזיר פלט".
4. **זיהוי שגיאות PHP בפלט**, כפי ש-PHP מדפיס אותן כש-`display_errors` פעיל:
   - `Fatal error:` / `Parse error:`: שגיאה בלוג. כנראה שהסקריפט לא הסתיים.
   - `Warning:` / `Notice:` / `Deprecated:`: אזהרה בלוג.

**סטטוס סופי:**

| מצב | סטטוס |
|---|---|
| HTTP 2xx, בלי שגיאות PHP בפלט | הצלחה |
| HTTP 2xx, עם Warning / Notice / Deprecated | הצלחה חלקית |
| HTTP 2xx, עם Fatal / Parse error | נכשל |
| HTTP שאינו 2xx (הפלט מוצג בכל זאת) | נכשל |
| הבקשה נכשלה (רשת / timeout) | נכשל |

> הזיהוי לפי טקסט. אם הסקריפט מדפיס בעצמו מילה כמו "Warning:" בהודעה רגילה, הסטטוס יהיה "הצלחה חלקית". הפלט המלא מוצג תמיד, כך שאפשר לבדוק.

## פעולה: בדיקת עדכון אחרון

- **מזהה:** `check_last_update`
- **קוד:** `FlightStatusSystem.kt`. הלוגיקה עצמה היא הפעולה הגנרית `core/remote/LastUpdateCheck.kt`, אותה פעולה כמו ב-[paisresults.co.il](paisresults.md#פעולה-בדיקת-עדכון-אחרון).

> מציגה מתי הקובץ `flights_data.json` בשרת עודכן לאחרונה (לפי שעון ישראל), וכמה זמן עבר מאז. אם הוא לא עודכן יותר מהסף, הוא מסומן כישן.

הפעולה קוראת בלבד. היא לא מורידה, לא מעלה ולא יוצרת תיקיות. לכן אפשר לתזמן אותה בתדירות גבוהה כ**ניטור**: אם הנתונים בשרת הפסיקו להתעדכן, מתקבלת התראה.

### מה היא עושה

1. **בדיקת הגדרות.** אם חסרים פרטי חיבור בהגדרות המערכת, הפעולה נכשלת מיד.
2. **התחברות** לשרת לפי הגדרות המערכת. כשל בחיבור: **נכשל**.
3. **הקובץ `flights_data.json`** בתוך תיקיית היעד:
   - FTP/FTPS: זמן השינוי מ-`MDTM` (UTC), ואם השרת לא תומך בו, מ-`MLST`. הגודל מ-`SIZE`.
   - SFTP: `stat` (זמן שינוי וגודל).
   - תשובה "הקובץ לא קיים" (FTP 550 / `SSH_FX_NO_SUCH_FILE`): **לא נמצא**.
4. **סיווג** (לפי הזמן במכשיר אחרי ההתחברות):
   - **עדכני:** עברו עד X שעות מהעדכון (הסף מההגדרות, ברירת מחדל: **שעה**).
   - **ישן:** עברו יותר מ-X שעות.
   - **לא נמצא** / **שגיאה**.
5. **סיכום בלוג:**
   - שורה לקובץ: תאריך ושעה + זמן שחלף. ירוק לעדכני, כתום לישן, אדום לחסר.
   - ספירה: עדכני / ישן / חסר או נכשל.
   - טבלה: קובץ | עדכון אחרון (שעון ישראל) | זמן שחלף | גודל | מצב.
   - שורת "הקובץ הישן ביותר" **לא** מוצגת, כי יש רק קובץ אחד.

**סטטוס סופי:**

| מצב | סטטוס |
|---|---|
| הקובץ עדכני | הצלחה |
| הקובץ ישן | הצלחה חלקית |
| הקובץ לא נמצא, שגיאה בקריאת הפרטים או כשל בחיבור | נכשל |

בהרצה מתוזמנת, כל סטטוס שאינו הצלחה שולח התראה (אם ההתראות פעילות).

### תצוגת זמנים

כמו ב-paisresults.co.il: `dd/MM/yyyy HH:mm:ss` לפי **שעון ישראל** (`Asia/Jerusalem`, כולל שעון קיץ), וזמן שחלף עד שתי היחידות הגדולות (למשל "לפני 42 דק׳"). זמן שינוי עתידי מוצג כ"… בעתיד" ונחשב עדכני.

| שדה | ברירת מחדל | הערות |
